# 报销单明细提取原型

此原型只输出候选明细供复核，不接入数据库，不调用外部 OCR，不更新发票报销状态。

## 使用

在 WSL Bash 中运行，文件参数使用 WSL 路径：

```bash
python3 scripts/extract_reimbursement.py /path/to/reimbursement.pdf --probe-only
python3 scripts/extract_reimbursement.py /path/to/reimbursement.pdf \
  --output-dir tmp/reimbursement-results \
  --work-dir tmp/reimbursement-work
```

第一条只检查可提取文字和 PDF 内容结构，不执行 OCR。第二条使用 Poppler 渲染、Pillow 切分列和文字行、本地 Tesseract 识别。省略 `--work-dir` 时中间图像存入临时目录并自动清理。输出 JSON 和 UTF-8 BOM CSV；号码以字符串保存、金额以两位小数字符串保存。Excel 打开 CSV 时必须把票号列作为文本导入，避免长号码丢失精度。

需要 `pdftotext`、`pdftoppm`、`tesseract`（`chi_sim` 与 `eng` 语言）、Python 和 Pillow。可选 pikepdf 用于详细结构检查。它们属于单独的本地分析环境；本次没有更改线上后端依赖或 Docker 镜像。

## Tesseract 资源模型

程序通过 Python `subprocess` 启动系统 `/usr/bin/tesseract`，模型从 `/usr/share/tesseract-ocr/5/tessdata` 读取。每次调用都是独立进程，处理结束即退出；不会常驻内存，不会访问网络，也不会调用百度 OCR。页面先由 `pdftoppm` 转成 300 DPI 灰度 PNG，再由 Pillow 在内存中裁剪成列和行，裁剪图暂存到工作目录供 Tesseract 读取。

目前每页最多并发 4 个 Tesseract 进程（`ThreadPoolExecutor(max_workers=4)`），但每个子进程设置 `OMP_THREAD_LIMIT=1`，避免“4 个进程各自再开多线程”。每个进程主要使用 CPU 和模型内存；本机样本运行时观察到单个进程约 61-64 MiB 常驻内存，最多约 4 个同时运行，实际负载约为 250 MiB 量级，另加 Python/Pillow 和渲染页面的内存。当前 WSL 环境报告 32 个逻辑 CPU、约 15 GiB 可用内存，所以 4 并发是保守的固定值，不是按机器无限扩张。

如果接入后端，不建议在 FastAPI 请求线程中直接运行；应放到 Celery/独立 worker，并设置并发上限、任务超时和临时目录配额。低配部署可以将 `max_workers` 降到 1 或 2；大量页面可以按页任务化，但需要控制总进程数。Tesseract 官方文档也建议：批量处理多张图时，将每个实例限制为单线程，再在进程层并行；否则默认线程数可能叠加。

## 识别范围和局限

- 当前布局为 A4 竖向的浙江大学预约报销确认单，六列依次为发票代码、号码、类别、日期、内容、金额。列位置由模板决定，未验证其他学校、页面缩放、倾斜扫描、旋转页或不同打印边距。
- 通过号码列定位行，再对日期和金额逐格识别；多行类别和开票内容单独切行。支持明细延续到下一页且不重复表头的样式，但不保证任意跨页断行都能识别。
- 未识别出合法日期的候选不计入明细；输出候选数量及成功行数量用于人工排查。结果不保证完整，所有行默认 `unreviewed`，禁止自动视作已经校对。
- 若代码栏是“数电票”，保留 `invoice_code_raw`，数字字段 `invoice_code` 为 null；不得把标签、票号前缀或其他字段填入代码。
- 保留原始 OCR 文本、中文内容的另一种分割模式输出、页面及行坐标。多个识别结果不一致会标记警告；没有警告也不代表识别准确。
- PDF 文字变成绘图轮廓后，普通文本提取无法还原字符；没有字体映射时不能把矢量路径直接当作 Unicode。此情形需要 OCR/字形识别，或从原系统另取 HTML、表格、保留文字的导出文件。
- 此版本会检查原生文字存在与否，但尚未实现原生文字表格解析。含文字层文档应在未来版本优先进入文字解析分支。

## 接入左栏模块前的规则

建议流程为“导入报销单 → 展示明细和原页 → 匹配当前用户的发票 → 确认后执行操作”。号码是匹配依据，日期和金额交叉校验；没有号码、多个候选、字段冲突或 OCR 可疑时必须显示待核对，不按名称猜测。报销申请总额可能包含没有对应发票的补贴，不能强制将申请总额视为发票金额合计。保留原文件、提取版本、来源页以及用户确认记录。

只进行了本地样本识别和逐项看图核对；自动 OCR 原文与人工/助手校对版本应分开保存。原文件、渲染图、明细结果及校对脚本必须放在 Git 忽略目录，不能作为仓库测试样本提交。
